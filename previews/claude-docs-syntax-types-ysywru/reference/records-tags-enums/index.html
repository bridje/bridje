Records, tags and enums

Keys

Section titled “Keys”

A key is declared once, at the top level, with the type of the value it holds:

decl: .name Str
Declares the key .name, holding a Str.
decl: {.name Str, .age Int}
Declares several keys at once.
decl: [a] .value a
Declares a key whose type has variables; each use of the key instantiates them afresh.

A key belongs to the namespace that declares it. Within that namespace it’s written .name; elsewhere, qualified by a require alias, m/.name. A tag’s declaration also declares its keys, if they aren’t already — see tags.

Each key defines two functions:

.name(r)
The value of .name in r. The type checker demands that r carries .name: {.age} lacks {.name}.
.?name(r)
The value of .name in r, or nil if it has none; accepts any record. Its type is the key’s, made nullable.

Records

Section titled “Records”
{.k1 v1, .k2 v2, …}
A record literal. Each value is checked against its key’s type: {.name 42} is an error, Int is not a subtype of Str.
with(r, .k1 v1, .k2 v2, …)
A copy of r, with each key set — added, or replaced. On a record parameter r, the result is r’s type, known to carry .k1 and .k2 as well.
set(r, .k, v)
Sets .k in r in place, returning its previous value, or nil. The record’s type doesn’t change.

A record’s type is the set of keys it’s known to carry; see type syntax.

A function whose last parameter is a record can be called without it, and receives an empty record — the trailing-options convention, read with .?opt.

Tags

Section titled “Tags”
tag: Name{.k1, .k2}
Declares the tag Name, over a record carrying .k1 and .k2.
tag: Name
Declares a nullary tag: Name is a singleton value.
tag: [a] Name{.k(a)}
Declares a tag with type parameters; .k(a) instantiates .k’s type variables, in order, at the tag’s.
Box{.value "s"} is a Box(Str).

A tag is distinct from every other tag, including one with the same keys. Tag names are capitalised.

Constructing

Section titled “Constructing”
Name{.k1 v1, .k2 v2}
A tagged value, from a record literal. In the literal, a bare key is looked up among the tag’s own keys first — other/Name{.k1 v} needs no other/.k1.
Name(r)
A tagged value, from a record held elsewhere.
Name
A nullary tag’s value.

The record must carry the tag’s keys — Pair{.fst 1} is {.fst} lacks {.snd} — and may carry more. A tag takes exactly one argument: Name(a, b) is an error.

Reading

Section titled “Reading”

A tagged value is a record carrying its tag’s keys: .k1(v), .?k3(v), and it passes wherever {.k1} is demanded.

Caution

with and set don’t yet work on tagged values.

Enums

Section titled “Enums”
enum: Name followed by tag: forms
Declares an enum over a fixed set of tags:
enum: Name(a, b) gives it type parameters, which its tags share.

Each variant is a tag in the declaring namespace, and a subtype of its enum. Ok{.value 1} is an Ok(Int, e); a value that may be an Ok or an Err is a Result(a, e). Enum names are capitalised.

Pattern matching

Section titled “Pattern matching”

case: and catch: branches match tags:

Name
A value with the tag Name, whatever its record.
Name(r)
A value with the tag Name, binding its record to r.
Name{k1, k2}
A value with the tag Name, binding k1 to its .k1 and k2 to its .k2. The keys are looked up among the tag’s own first. A pattern checks the tag alone: the keys a destructuring reads must be present when it matches.
x (lowercase)
Any value, nil included, bound to x. In an enum case, its type is narrowed to the variants not yet matched.
m/Name, m/Name(r), m/Name{k}
A tag from another namespace.

A case over an enum must name every variant, or have a default or catch-all.
